# Contributing to Nimbus

Thanks for wanting to help. A few ground rules keep this sustainable.

By submitting a contribution you agree that:

2. **You certify the Developer Certificate of Origin**

   appreciated but the act of opening a PR is taken as your certification.

If you can't accept that (for example, your employer owns your work), please
sort that out before opening a PR.

## Before you open a PR

- **Build + test.** `pio test -e native` must be 100% green, and
  `pio run -e esp32s3` must compile. See docs for the full environment list.
- **Pre-commit hooks.** Install once with `pip install pre-commit && pre-commit
  install`. CI runs the same hooks (`pre-commit run --all-files`) and will fail
  loudly if they don't pass. The lizard complexity gate applies to new code
  only - existing offenders are baselined in `tools/release/lizard_whitelist.txt`
  (the whitelist only shrinks; don't add to it without discussion).
- **No repo-wide reformatting.** Formatting-only diffs of code you didn't
  otherwise change will be declined.
- **Docs follow code.** If you rename or move anything user-visible, update the
  docs in the same PR (grep for the old wording). Generated files
  (`website/docs/**` under guides/reference, `docs/sfx-map.md`,
  `lib/core/include/nimbus/docs_pack_data.h`) are regenerated by their
  scripts - edit the source, re-run the generator, commit both.
- **Hardware claims need hardware.** "Compiles" is not "works" here. If your
  change touches device behavior and you don't have a board, say so in the PR -
  a maintainer will run the hardware-in-the-loop suite.

## What makes a good first contribution

- Docs fixes and build-guide clarifications (especially from your own first
  build - every stumble you hit is a docs bug we want).
- New sound-pack variants or LED themes.
- Additional display/board support behind the existing driver seams.

## Conduct

Be kind. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
