# Lane CLAMP: does a small wallet get a capped retry, or a park?

Date: 2026-11-04 (all timestamps date -u). Tree: lanes/CLAMP/nimbus, base 28813029, head 04dcd5aa.
Silent mode held throughout (no audio of any kind; no board in this lane).

## The cause, at file:line

Bench row S10 (evidence/bench-5.0.0/v5-28813029/S10/, program evidence root) injected the clamp 402 via
PROVFAULT and the device logged "cumulo refused the request (billing) - no same-host retry", failed over to
anthropic with an "out of credit" notice, and no capped resend happened.

1. The bench fixture body is CORRECT. It is byte-for-byte the real router body: cumulo-nimbus main
   (aae251e) packages/shared/src/router-refusals.ts routerRefusal() builds {error, reason, message,
   charged:false, retryable, ...fields} and apps/api/src/router-service.ts creditRefusal() (lines 306-341)
   adds balanceCredits, availableCredits, heldCredits, estimatedCredits, maxAffordableOutputTokens and
   retryHint "lower_max_output". The S10 body carries every field. Nothing is missing.

2. The firmware's TEST seam was wrong. lib/harness/src/providers/wire.h, the NIMBUS_TEST/NIMBUS_NATIVE
   override block in exchange() (base 28813029 lines 400-417): when PROVFAULT was armed, the scripted
   answer was parsed and returned BEFORE pd.http->execJson. That early return bypassed:
   - the RouterTap the cumulo head installs as pd.http (src/agent/orchestrator.cpp cumuloAttempt), so
     runLadder never saw the reason, the typed cause stayed empty, and the native head's plain "HTTP 402"
     error classified as StepErr::Billing (lib/core/src/orch_head_loop.cpp classifyHttpStatus) - hence
     "no same-host retry" and the "out of credit" failover notice;
   - the wire's resend loop (wire.h base lines 449-459, prepareRouterResend) - so the capped resend could
     never run under PROVFAULT, on any build.
   Row S10 wants the "resending once with the output capped" line, so S10 was unpassable by construction.

3. Production (no NIMBUS_TEST) was already correct and host-proven: the same wire loop, fed the exact
   contract body by a scripted transport, resends once capped at 74904 and serves
   (test/test_router_refusal_contract test_the_clamp_resends_once_capped_and_serves, green on the base).

## The fix (head 04dcd5aa)

The scripted answer moves to the transport's seat:
- agent::TestAnswerTransport (lib/harness/include/nimbus/harness/test_answer_transport.h,
  NIMBUS_TEST/NIMBUS_NATIVE only) wraps the real transport, answers the armed host locally with the same
  log line text as before, forwards everything else.
- deviceTransport() (src/agent/transport_tls.cpp) installs it under NIMBUS_TEST, so the scripted answer
  enters UNDER the RouterTap and INSIDE the resend loop: a scripted refusal walks the production path.
- wire.h keeps only the UNSENT verb (kTestUnsentStatus); the answered case is deleted.
- vision_caption and embeddings keep their own override checks (their seams do not pass through wire
  exchange; the vision seam can already exercise its own capped resend under PROVFAULT).
- bench row S10's stale docstring ("PROVFAULT answers before the transport") is corrected in
  tests/hil/bench_rows.py; the row's OPEN grade now says what still needs a low-wallet account: a served
  capped reply (the single scripted 402 proves the resend ran and the honest handling).

## Does the candidate need a rebuild?

YES. The candidate 28813029 carries the defective test seam, so bench row S10 cannot pass on it and, worse,
measures a false out-of-credit failover. A rebuilt candidate with 04dcd5aa (or its merge) lets S10 show the
capped resend and the honest clamp handling on the bench board. Production behavior (no PROVFAULT) is
unchanged by this fix; the rebuild is needed for the bench proof, not for live correctness.
